### `tests/client/ShotPredictor.test.js`

**Переписать существующий тест** (`tests/client/ShotPredictor.test.js:282-294`),
который сейчас закрепляет именно багованное поведение:

```js
expect(created.w2).toEqual({ [localId]: null, a7: bombData });
```

Новое ожидание: серверная строка до клиента **не доезжает**, локальная
не гасится — сущность уже стоит под `L<n>` и остаётся под ним:

```js
expect(created.w2?.a7).toBeUndefined();
expect(created.w2?.[localId]).toBeUndefined();
```

(в зависимости от того, что осталось в кадре, ключа `w2` может не быть
вовсе — проверять через `?.`, а не `toEqual` по всему объекту).

**Новые тесты:**

1. **`null` детонации переименовывается в локальный id.** Спавн → кадр с
   `{ w2: { a7: bombData } }` (подтверждение) → кадр с
   `{ w2: { a7: null } }` → на выходе `{ w2: { L1: null } }`, ключа `a7`
   нет. Это прямая регрессия основного бага: именно так сущность
   удаляется без пересоздания.
2. **Алиас переживает `resetLocal()`.** Спавн → подтверждение →
   `resetLocal()` (смерть игрока, keySet) → кадр с `{ w2: { a7: null } }`
   → всё ещё `{ w2: { L1: null } }`. Без этого теста легко вернуть
   регрессию «призрачная бомба», описанную в
   [stage_1.md](stage_1.md#13-два-вида-сброса).
3. **`reset()` хоронит неподтверждённую бомбу.** Спавн без подтверждения
   → `reset()` → ближайший `filterServerSnapshot` отдаёт
   `{ w2: { L1: null } }`.
4. **Алиас снимается по возрасту.** Спавн → подтверждение → вызов
   `filterServerSnapshot` с `localNow + BOMB_ALIAS_MAX_AGE + 1` → карта
   алиасов пуста (проверять через приватное поле, как это уже сделано в
   соседних тестах файла, либо через поведение: последующий `a7: null`
   больше не переименовывается).
5. **Чужая бомба не трогается** — существующее поведение не должно
   сломаться: строка с `data[5] !== myId` и `null` чужой детонации
   проходят напрямую. Если такой тест уже есть — убедиться, что он
   зелёный, отдельный не заводить.

## Документация

По правилу актуализации из [CLAUDE.md](../CLAUDE.md) («клиентские
модули/parts/предикторы → `client.md`») правится **в обеих языковых
папках в том же изменении**.

`docs/ru/client.md:76` сейчас описывает старое поведение:

> **подавление серверных дублей** (`filterServerSnapshot`) … своя бомба —
> при подтверждении локальная сущность (`L<n>`) убирается, серверная
> становится авторитетной

Заменить на описание алиасов, примерно:

> своя бомба — при подтверждении серверная строка до клиента не доезжает,
> а её id запоминается как алиас локального (`L<n>`): сущность живёт под
> локальным ключом от спавна до детонации, и `null` взрыва
> переименовывается в него же. Так бомба не пересоздаётся — иначе
> перезапускались бы её таймер и одноразовый звук постановки. Алиасы
> снимаются `null`'ом детонации, по возрасту (`BOMB_ALIAS_MAX_AGE`) и
> полным `reset()`; смена keySet (`resetLocal()`) их **не** трогает,
> потому что keySet приходит раньше кадра с детонацией.

Симметрично — в `docs/en/client.md` (та же позиция в списке).

Там же, в разделе про звук, добавить строку про `releaseSound`:
`unregisterSound` останавливает звук вместе с владельцем,
`releaseSound` — снимает регистрацию, но даёт одноразовому сэмплу
доиграть (луп всё равно останавливается).

Отдельного журнала изменений в проекте нет — записи не требуются.

Ручной прогон в браузере (`npm run dev`, два окна — два игрока):

1. **Основной сценарий**: поставить бомбу под собой → сэмпл
   `bombHasBeenPlanted` звучит **один раз и целиком**, без обрыва
   посередине; спрайт бомбы не моргает, цифра таймера не перескакивает.

   «0»), звук взрыва отрабатывает как раньше.

   бомбы исчезает по взрыву, призрака не остаётся. Отдельно послушать
   узкое окно из [stage_1.md](stage_1.md#известное-узкое-место-принять-и-проверить-руками)
   — смерть в первые ~150 мс после постановки.
5. **Смена карты и рестарт раунда**: полотно чистое, повторная постановка
   бомбы работает штатно (алиасы и pending сброшены полным `reset()`).
6. **Регресс по трассерам**: стрельба `w1` — трассеры не задваиваются и
   не пропадают (ветка `hitscan` не менялась, но она соседняя).
