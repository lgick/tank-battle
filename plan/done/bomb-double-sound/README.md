# План: двойной звук постановки бомбы

## Проблема (кратко)

Ставишь бомбу — сэмпл `bombHasBeenPlanted` слышен дважды: старт, обрыв
через ~100-200 мс, повторный старт с начала.

Причина — в клиентском предикте выстрела. `ShotPredictor.tryFire()`
мгновенно спавнит **локальную** бомбу под ключом `L<n>`, а когда приходит
серверное подтверждение, `filterServerSnapshot()` гасит локальную строку
`null`'ом, **оставляя серверную**. Оба изменения попадают в один объект
кадра, `GameCtrl.parse` проходит по нему `for…in`: `L1: null` уничтожает
локальный `Bomb` (и обрывает звучащий сэмпл), `a7: [...]` создаёт новый
`Bomb`, который регистрирует сэмпл заново.

Полный разбор — в [stage_1.md](stage_1.md).

Тот же баг был найден и исправлен в родственном проекте (движок VIMP +
плагин `vimp-tanks`); здесь применяется то же решение, адаптированное под
JS-версию предиктора, вместе с уроками, полученными там на код-ревью
(не сносить алиасы по `KEYSET_DATA`, хоронить неподтверждённые бомбы).

## Стадии

| Стадия | Содержание | Статус |
| --- | --- | --- |
| [stage_1.md](stage_1.md) | Алиасы бомб в `ShotPredictor`: сущность живёт под локальным id от спавна до детонации | ✅ выполнен |
| [stage_2.md](stage_2.md) | `SoundManager.releaseSound()` + `Bomb.destroy()`: одноразовый сэмпл доигрывает | ✅ выполнен |
| [stage_3.md](stage_3.md) | Тесты (`ShotPredictor`, `SoundManager`) и документация `docs/{en,ru}/client.md` | ✅ выполнен |

Стадии 1 и 2 независимы, но **обе обязательны**: стадия 1 убирает
пересоздание сущности, стадия 2 — обрыв сэмпла при штатной детонации
(`w2.time = 300` мс, то есть бомба физически живёт меньше сэмпла).

## Затрагиваемые файлы

- `src/client/ShotPredictor.js` — алиасы, `resetLocal()`, похороны pending
- `src/client/main.js` — `KEYSET_DATA` зовёт `resetLocal()`, не `reset()`
- `src/client/SoundManager.js` — новый `releaseSound(id)`
- `src/client/parts/Bomb.js` — `destroy()` переводится на `releaseSound`
- `tests/client/ShotPredictor.test.js`, `tests/client/SoundManager.test.js`
- `docs/en/client.md` + `docs/ru/client.md` (зеркально, в том же изменении)

Изменения только клиентские: серверный протокол, формат кадра и
`src/config`/`src/data` не трогаются.
